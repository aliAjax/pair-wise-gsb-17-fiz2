# hxwl-03 钻孔取样与试验跟踪台

在钻孔分层编录基础上补建的取样与试验跟踪台：按孔按回次登记原状样、扰动样、标贯与岩芯样，
现场自动判定，实验室点收核对，结果合格即冻结入库，现场更正另建带原因版本。

## 技术栈

React + Vite + TypeScript + CSS（无新增依赖，数据沿用本机 localStorage）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5103。首次打开自动播种 3 个钻孔的分层资料与 9 条覆盖各状态的历史样件；
页内「恢复本地示例数据」可随时重置。

## 业务规则

现场登记（每个孔按回次）：
- 记录样号、起止深度、样型、取土器/标贯器编号、封样时刻。
- 深度须完整落在已编录某一地层内（边界容差 0.05m），跨层或超出孔深 → 待复核，记录深度差。
- 样号全项目唯一，重号 → 待复核。
- 封样时刻早于登记时刻超过 2 小时 → 待复核。
- 待复核样件不能送检，经「复核修改」重判合格后转入待送检。

实验室环节：
- 送检时登记申报重量；实验室按清单逐件点样号、称重量。
- 少样（样号未到）整批退回；实收重量少于申报 0.05kg 以上退回，均记录退回原因。
- 核对通过后写入试验结果：合格 → 结果写入并冻结原记录，状态「已入库」；
  不合格 → 登记原因并退回。

更正与留痕：
- 已冻结记录不能改、不能删；「现场更正」会保留原记录并另建带原因的新版本（v2、v3……），
  原记录标记被替代并留档，新版本按当前分层重新判定。
- 每次登记、修改、送检、收样、结果、退回、更正均写入操作留痕。

页面重开后：状态保留，顶部指标卡与页签区分待复核 / 待送检 / 已送检 / 已入库 / 退回；
台账支持按孔号筛选、关键词检索（孔号、样号、取土器、退回与更正原因、结果、判定问题），
以及「深度差 ≤ n m」数值过滤。

## 代码分层

```
src/
  data/      资料层：领域类型 types.ts、时刻工具 time.ts、钻孔分层与播种数据 seed.ts
  rules/     判定层：现场核对 validate.ts、状态流转/冻结/版本 workflow.ts
  storage/   保存层：localStorage 读写与播种/重置 trackerStore.ts
  components/ 界面层：SampleForm、Tracker、LabDialogs、Modal
  App.tsx    界面装配，不直接包含判定规则
```

各层单向依赖（界面 → 判定/保存 → 资料），可在不改界面的前提下替换为后端 API 或 IndexedDB。
